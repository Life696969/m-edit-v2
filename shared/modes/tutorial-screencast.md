# Tutorial and screencast mode

## Goal

Make every demonstrated action legible and synchronized with the explanation.

## Plan

- Identify the task, starting state, steps, errors, decision points, and final result.
- Crop or zoom only to the active control; preserve enough context for orientation.
- Keep cursor movement natural and visible. Avoid fake cursor paths unless the guide explicitly reconstructs them.
- Place captions away from menus, code, form fields, and status messages.
- Use step labels, callouts, highlights, and keyboard overlays only when they reduce ambiguity.
- Remove waiting time carefully while preserving cause and effect.
- When code or terminal text matters, prioritize readable resolution over decorative framing.
- Show the completed result long enough to verify it.

## Common failures

- tiny unreadable interface capture
- captions covering the control being explained
- cuts that hide whether an action succeeded
- zooms with no orientation reset
- excessive cursor effects or fake UI

## Review

Test at the intended mobile/desktop viewing size. A first-time viewer should be able to reproduce the workflow without guessing hidden actions.
